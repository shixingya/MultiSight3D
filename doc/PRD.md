## 1. 产品概述

### 1.1 一句话定位
MultiSight3D 是一套**自研开源多视图摄影测量（Multi-View Stereo Photogrammetry）管线**：用普通手机/相机环绕拍摄的几十到几百张照片，自动重建出带真实纹理的物体三维模型（OBJ / PLY / GLB）。

### 1.2 背景与机会
- 三维资产需求爆发：电商展示、3D 打印、文物数字化、游戏/手办资产、数字孪生等场景都需要低成本获取物体级三维模型。
- 现有方案的断层：
  - **专业软件**（RealityCapture、Metashape）：精度与速度优秀，但闭源、授权昂贵（数千至数万美元/年）。
  - **开源管线**（COLMAP、Meshroom）：免费但工程化程度低——依赖配置复杂、显存占用高、对新手不友好、输出到 GLB 需多工具拼接。
  - **消费级 App**（Polycam、Luma、Kiri）：易用但闭源、精度受限、导出收费、数据不可控。
- 机会点：做一套 **「一条命令进，一个 GLB 出」** 的开源管线——比 COLMAP 更易用、比 App 更可控、可嵌入第三方产品（卜天 Butian3D 云平台/桌面端即为内部集成方）。

### 1.3 与卜天三维（Butian3D）的关系
MultiSight3D 是独立的开源引擎项目，采用「物体级重建」切入（Butian3D 面向无人机大范围场景）。架构上保持引擎适配器兼容，未来可作为 Butian3D 桌面端 MokEngine 的开源替代/降级方案接入其 Web 流水线（`ENGINE=multisight`）。

## 2. 目标用户与使用场景

### 2.1 用户画像
| 画像 | 描述 | 关键诉求 | 优先级 |
| --- | --- | --- | --- |
| P-1 中小文保/博物馆技术方 | 需要文物高精度数字化存档 | 精度、可控、数据私有、低成本 | 高 |
| P-2 3D 打印/手办/电商从业者 | 把实物变成可打印/可展示的模型 | 简单快捷、纹理好、GLB 直出 | 高 |
| P-3 开发者/研究者 | 集成重建能力到自己的产品 | CLI/API、可魔改、开源协议友好 | 中 |
| P-4 摄影测量爱好者 | 学习 SfM/MVS 原理 | 过程可视化、文档、参数可调 | 中 |

### 2.2 核心场景（User Journey 摘要）
1. **手机拍物**：用户在转盘/自然光下环绕物体拍 30–150 张照片 → 拖入 WebUI 或一个目录交给 CLI → 等待 → 预览 → 下载 GLB 用于展示/打印。
2. **文物存档**：技术人员按拍摄规范采集 → 管线重建 → 导出 OBJ + 稠密点云交付给存档系统 → 全流程本地完成，数据不出内网。
3. **开发者集成**：以 `multisight reconstruct --in photos/ --out model.glb` 嵌入自动化资产生产线，或以库形式调用各阶段 API。

## 3. 竞品与对标

| 方案 | 类型 | 优势 | 我们的差异化 |
| --- | --- | --- | --- |
| COLMAP | 开源 SfM/MVS | 学术标杆、精度好 | COLMAP 无纹理网格闭环；我们提供端到端 GLB 直出与更低门槛 |
| Meshroom | 开源节点式管线 | 节点编辑灵活 | 依赖重（Qt/Alembic）、速度慢；我们 CLI 优先、增量轻量 |
| RealityCapture | 商业 | 速度、精度顶级 | 闭源昂贵；我们开源、可商用可审计 |
| Polycam/Luma | 消费 App | 极易用 | 闭源、导出收费、精度有限；我们本地跑、精度可控、数据私有 |
| nerfstudio/3DGS 系 | 开源神经渲染 | 视觉效果惊艳 | 辐射场不可直接用于测量/打印；我们输出传统 mesh，兼容既有工具链 |

> 定位结论：**「传统摄影测量精度 + 消费级易用性 + 开源可集成」** 的三角中间地带。

## 4. 产品目标与非目标

### 4.1 目标（v1.0 范围内）
- G1：单条命令完成「照片目录 → 纹理网格」全流程，中间产物自动落盘、可断点续跑。
- G2：物体级重建质量达到实用：主流测试集上重建成功率 ≥ 80%，几何误差 ≤ 物体尺寸的 1%（详见 §8 指标）。
- G3：开箱即用的 WebUI：上传、进度、3D 预览、下载。
- G4：消费级硬件可跑：16GB 内存 + 8GB 显存（或纯 CPU 降级模式）完成 ≤150 张照片的物体重建。
- G5：开源可维护：模块化解耦、文档齐全、CI 覆盖核心算法回归测试。

### 4.2 非目标（明确不做）
- ❌ 大范围地理场景/无人机空三（属 Butian3D 场景线）。
- ❌ 神经辐射场 / 3D Gaussian Splatting 作为主输出（可作为后续可选模块）。
- ❌ 实时/在线增量重建（SLAM）。
- ❌ Windows 图形化专业软件（对标 Metashape UI 的重客户端）。
- ❌ 云端托管 SaaS 服务运营（提供自托管 Docker 镜像即可）。

## 5. 功能需求

### 5.1 管线总览
```
照片输入 → [S1 预处理] → [S2 SfM 稀疏重建] → [S3 MVS 稠密重建] → [S4 网格与纹理] → 模型输出
```

### 5.2 功能需求清单
优先级：P0 = v0.x 必须；P1 = v1.0 必须；P2 = 增强项。

| ID | 需求 | 说明 | 优先级 |
| --- | --- | --- | --- |
| FR-01 | CLI 一键全流程 | `multisight reconstruct -i photos/ -o out/`；支持 `--from-stage` 断点续跑 | P0 |
| FR-02 | S1 图像预处理 | 格式校验(jpg/png)、EXIF 焦距/方向读取、分辨率降采样档位、模糊照片检测与剔除建议 | P0 |
| FR-03 | S2 特征提取匹配 | 局部特征（SIFT 基线，ALIKED/DISK 等学习型特征作为加速选项）+ 几何验证 | P0 |
| FR-04 | S2 增量 SfM | 相机内外参求解、位姿注册、三角化稀疏点云、捆绑调整（BA）；输出 COLMAP 兼容模型目录 | P0 |
| FR-05 | S3 稠密点云 | MVS 深度图估计 + 多视图融合去噪；支持显存不足自动分块 | P0 |
| FR-06 | S4 网格重建 | 泊松重建/Delaunay 可选、空间裁剪（去除地面与噪点团）、减面（QEM） | P0 |
| FR-07 | S4 纹理映射 | UV 展开 + 多视图纹理烘焙、接缝优化、遮挡视图剔除；输出 4K 内嵌纹理 | P0 |
| FR-08 | 输出格式 | OBJ+MTL+贴图、PLY（点云与网格）、GLB（单文件直出）；坐标系 Y-up 归一化 | P0 |
| FR-09 | 质量自检报告 | 每阶段输出 JSON 报告：注册率、重投影误差、点数、网格水密性检查、警告与建议 | P1 |
| FR-10 | WebUI | 拖拽上传、参数预设（标准/精细/快速）、SSE 实时进度、结果 3D 预览（three.js）、打包下载 | P1 |
| FR-11 | 拍摄引导 | 输入照片不足/覆盖不够时给出具体补拍建议（方位、重叠度）；附交互拍摄规范文档 | P1 |
| FR-12 | 纯 CPU 降级模式 | 无 GPU 时 MVS 用 CPU 实现，速度换可用性 | P1 |
| FR-13 | 批量任务 | 多物体目录批处理、队列管理 | P2 |
| FR-14 | Python SDK | 各阶段可单独 import 调用，供开发者集成 | P2 |
| FR-15 | 透明物体/无纹理物体辅助 | 散斑投射图案导入、掩膜输入去除背景/反光 | P2 |

### 5.3 WebUI 交互要求（FR-10 展开）
1. 首页：拖拽/选择照片（≤500 张，单张 ≤20MB），显示张数与预估耗时。
2. 任务页：阶段时间线（预处理→稀疏→稠密→网格→纹理），每阶段百分比与日志尾部；失败时给出归因（照片质量/位姿注册失败/显存不足）与补救建议。
3. 结果页：3D 查看器（旋转/缩放/线框切换、白昼/环境光预设）、模型统计（面数/纹理尺寸/尺寸估计）、下载区（GLB/OBJ/PLY/报告）。
4. 全部本地运行，无账号无上传外发（隐私即卖点）。

## 6. 非功能需求

| ID | 类别 | 要求 |
| --- | --- | --- |
| NFR-01 | 性能 | 100 张照片物体重建：RTX 4070 级 ≤ 15 分钟（标准档）；快速档 ≤ 6 分钟 |
| NFR-02 | 资源 | 标准档峰值显存 ≤ 6GB、内存 ≤ 12GB；提供低配档（照片降至 1024px） |

## 8. 成功指标（v1.0 发布后 3 个月）
- 质量：标准测试集重建成功率 ≥ 80%；尺寸误差 ≤ 0.5%（有参照物时）。
- 体验：CLI 冷启动到首个结果 ≤ 30 分钟（含安装）；WebUI 任务失败率 ≤ 15%。
- 开源：GitHub Star ≥ 300；外部贡献 Issue/PR ≥ 20；Docker Pull ≥ 1000。

## 9. 技术架构概要（供 ARCHITECTURE.md 细化）
- **语言与栈**：Python 3.11 编排层 + C++/CUDA 计算核（或 PyTorch 学习型算子）；COLMAP 兼容模型目录作为 SfM 中间格式。
- **模块边界**：`preprocess / sfm / mvs / mesh / texture / report` 六包，以工作目录 `workspace/<task>/` 下标准工件（images.txt、cameras.txt、depth/、fusion.ply、mesh.obj、texture.png）交接。
- **算法选型基线**：特征 SIFT→ALIKED；匹配 LightGlue 可选；BA Ceres；MVS 先传统 PatchMatch（GIPUMS/NeuralPoiscer 类可替换）；网格 Poisson；纹理视差感知烘焙。
- **WebUI**：FastAPI + SSE（复用 Butian3D 服务端经验）+ 前端 three.js 预览（复用 ReconScene 资产加载位）。
- **硬件抽象**：设备探测（CUDA/MPS/CPU）自动选档。

## 10. 风险与对策
| 风险 | 等级 | 对策 |
| --- | --- | --- |
| 自研 MVS/纹理质量不及 COLMAP 生态 | 高 | 阶段接口兼容 COLMAP 目录格式，允许「自研/外接」双实现灰度对比 |
| 弱纹理/反光/透明物体成功率低 | 高 | 明确边界（PRD 声明适用物体类型）+ FR-15 辅助能力 + 拍摄规范前置教育 |
| 显存墙导致长任务失败 | 中 | 分块深度估计 + 断点续跑（NFR-04）+ 低配档 |
| 依赖许可证传染（如部分 MVS 库非商用友好） | 中 | NFR-06 许可证审计前置到选型阶段 |
| 范围膨胀（大场景/3DGS 诱惑） | 中 | §4.2 非目标清单为需求评审红线 |
| Windows 环境安装地狱 | 中 | 首选 Docker + 预编译 wheel；pip 一键安装为硬指标 |

## 11. 待决策点（需产品负责人拍板）
1. **算法自研深度**：SfM 阶段是完全自研，还是「薄封装 COLMAP 核心 + 自研前后处理」起步、逐步替换？（影响 v0.1 工期约 3–6 倍）
2. **MVS 技术路线**：传统 PatchMatch（CPU 友好）vs 学习型深度网络（GPU、需模型资产）作为首发？
3. **首发平台权重**：CLI+Docker（开发者向）与 WebUI（小白向）谁先做深？当前里程碑按 CLI 先行排布。
4. **品牌与协议**：仓库名 MultiSight3D 是否同步注册文档站域名；许可证 Apache-2.0 还是 BSD-3。

## 12. 附录：术语表
- **SfM**（Structure from Motion）：从多视角照片恢复相机位姿与稀疏三维点。
- **MVS**（Multi-View Stereo）：在已知位姿下估计逐像素深度，融合为稠密点云。
- **BA**（Bundle Adjustment）：对相机参数与三维点的联合非线性优化。
- **空三**：航空摄影测量术语，即区域网空中三角加密，对应本管线 SfM 阶段。
- **水密网格**：无缝封闭的三角网格，3D 打印的前置条件。
- **UV 展开/纹理烘焙**：将三维表面映射到二维贴图并回填照片颜色的过程。
